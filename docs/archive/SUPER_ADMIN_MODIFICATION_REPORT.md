# Super Admin Modification Report

## Scope

The Super Admin panel now treats PostgreSQL as the only source of truth for factories, factory owners, subscriptions, payments, usage, and token usage. No mock, demo, random, or fallback factory records are generated by the Super Admin frontend or backend.

## Random / Mock Data Removal

- Inspected Super Admin frontend and backend for `mock`, `demo`, `sample`, `random`, `dummy`, `fallbackFactories`, and hardcoded factories.
- No hardcoded Super Admin factory arrays were kept.
- Super Admin owners and factories pages now show empty states when the API returns an empty array:
  - `No real factory owners found yet.`
  - `No factories found.`
- Dashboard token count now comes from real `token_usage_logs` aggregation instead of a static placeholder.

## Owner Creation Flow

Super Admin can create a real factory owner from `/munshi-control-room/owners`.

Backend behavior:
- Validates password confirmation.
- Requires email or phone.
- Normalizes phone to E.164 and local lookup format.
- Blocks duplicate email and phone.
- Creates a real `factories` row.
- Creates a real `users` owner row linked by `factory_id`.
- Sets `factories.owner_id` and `factories.owner_phone_number`.
- Stores subscription, payment, usage limit, token limit, address, and admin note fields on the factory.
- Writes audit log action `CREATE_FACTORY_OWNER`.

## Subscription Edit Flow

Super Admin can edit a factory subscription from owners and subscriptions pages.

Editable fields:
- plan
- subscription status
- payment status
- billing cycle
- expiry date
- usage limit
- token limit
- admin note

Every subscription update writes an audit log with old and new values.

## Usage / Token Tracking Design

Added lightweight real tracking:

- `app_usage_logs`
  - login events
  - AI supervisor calls
- `token_usage_logs`
  - AI supervisor call records
  - token counts are stored as null until provider token counts are exposed by the AI flow.

Super Admin usage page:
- `/munshi-control-room/usage`
- Shows total app events, total tokens, monthly tokens, last active date, app logs, and token logs.

## Security Checks

- `/api/super-admin/*` remains protected by separate Super Admin JWT verification.
- Normal owner JWT/session is not accepted by Super Admin APIs.
- Super Admin token remains separate in `sessionStorage` under `munshi_super_admin_token`.
- Super Admin route is still hidden from normal app navigation.
- Passwords are hashed server-side and never returned.
- Factory delete now soft-deactivates by default. Hard delete requires explicit `hard_delete=true`.

## Tests Added

- Empty Super Admin owners/factories APIs render empty states, not mock data.
- Mock/demo/sample/dummy names are not shown when backend returns empty arrays.
- Add Factory Owner modal validates password confirmation.
- Admin mutation test remains opt-in via `PLAYWRIGHT_ENABLE_ADMIN_MUTATION_TESTS=true`.

## Known Limitations

- Exact AI token counts are not available from the current AI supervisor response. Token logs are real records, but token counts remain null/0 until provider usage data is exposed.
- Production mutation tests are disabled by default and should only be enabled with dedicated test credentials and test factory data.
- Bulk factory deletion is available only through the Super Admin factories page and is disabled unless `ENABLE_SUPER_ADMIN_BULK_DELETE=true`. See `BULK_DELETE_IMPLEMENTATION_REPORT.md`.
